## Subsequent native source work: FLAC disk admission

`scripts/actors/core/actor_audio.gd` now budgets completed FLAC decode-cache files on admission. A process-wide mutex serializes inventory, eviction, completed-file promotion and WAV resource loading; FFmpeg decodes run outside it with unique temporary paths. Other source paths with identical compressed content reuse the completed result when available. Completed lowercase SHA-256 WAV names are the shared FLAC cache namespace, including existing entries. Native preview admission charges at most 512 MiB and 256 completed files. Inventory work visits at most 4096 directory entries and refuses admission if inventory cannot be safely completed or enough old entries cannot be removed.

Access order is maintained in memory; prior-session files use modification time as the eviction fallback. Cache hits in the strong RAM cache do not rescan disk. The current requested entry is protected during pruning. Source assets and PCM already held by open documents/players are never modified. Linked entries/directories, unrelated filenames and in-progress decoder files are excluded from eviction. This is an in-process completed-cache admission policy, not an operating-system quota, external-writer sandbox, idle cleanup service or process-wide RAM ceiling.

Before decoding, the native FLAC STREAMINFO header must declare a mono/stereo frame count whose PCM16 data fits below 128 MiB with header room. Unknown-count, multichannel or larger preview sources are refused visibly. Decoder output also has a file-size safety stop and completed-size check. Successful owned temporary files are promoted only after admission; cancelled/refused temporary files are removed after confirmed decoder exit. Uncertain-exit files remain recoverable and are not pruned by this policy. Original-path FFmpeg rendering remains streaming and does not require native preview decoding; selecting/importing a huge file into the native UI remains limited.

## Subsequent native source work: optional MIDI sustain

The instrument inspector now offers **Render MIDI sustain pedal (CC64)** for sources retaining channel events. It defaults off, is Undoable, is disabled for locked/frozen tracks, and persists in actor values and pattern presets/JSON. Replacing a MIDI pattern with an ordinary preset clears the prior sustain policy along with unrelated maps/events. `audio_tempo_map.gd` validates the policy as a boolean. MIDI import warnings point to the option and retain the limitations of other controllers.

`audio_midi.gd:sustain_copy` creates derived note gates from ordered CC64 down/up intervals using threshold 64. All channel events at a note-off beat take effect before the note-off; same-beat CC64 events retain encounter order. An unreleased pedal ends at the source pattern boundary (or the last note end when no explicit boundary exists). Half-pedaling, all-notes-off/reset controllers, pressure, bend and later program changes are not performed. One-shot/drum and monophonic patches retain their own gate/voice behavior. This is a deterministic bounded source policy, not hardware sustain or a complete General MIDI engine.

The shared session render helper applies this copy before existing step/groove and instrument rendering, so asynchronous preview and snapshot audio export use the same policy and source tempo map. Preview signatures include the policy and retained events when enabled, preventing reuse of old derived PCM. Edited source notes and raw MIDI channel events are not rewritten; MIDI export still emits original gates/controllers for another player to interpret. The piano roll continues to display the editable original notes rather than pedal-expanded copies. Existing per-source note/event/time limits and cancellation remain in force.

Five production paths change: `audio_midi.gd`, `audio_edit_session.gd`, `audio_tempo_map.gd`, `audio_preset.gd` and `audio_workspace.gd`. ## Subsequent light source work: timeline notes MIDI

New `audio_midi_timeline.gd` provides a pure-data note projection without decoding or rendering PCM. The **Export Timeline Notes MIDI** command opens a scope/limits explanation and submits an immutable document snapshot to the existing cancellable job queue. Session/revision checks reject stale job completion and stale file-picker returns. It uses the existing bounded SMF writer and protected publisher. Existing **Export MIDI** remains source-pattern export.

Each note gate maps through its independent source tempo map/BPM and pending source-window retime, intersects the clip source window, expands source loops, optionally reverses the selected window, and maps speed/placement into absolute timeline seconds. The project step conductor converts both resulting boundaries into exported quarter-note beats and supplies tempo/meter events. Notes crossing a trimmed boundary become retriggered MIDI gates at that edge; audio envelopes/tails are not reconstructed. Whole-semitone static clip pitch is projected; fractional-semitone pitch, clip pitch automation and frozen note tracks are explicitly refused. Direct clip/track mute and routing-aware solo filter included sources. Routing/sends, group gain/pan/effects, other automation and audio-only clips are not MIDI data.

Enabled CC64 sustain uses the same render-only gate-copy helper. Shared step preprocessing supplies swing/lane state/accent variation; deterministic note probability, accent and ratchet gates are projected. Sample one-shot durations, synth envelopes/voice allocation, effects, modulation and other controller behavior are excluded; this is musical note export, not an audio-equivalent renderer. Raw channel events are deliberately omitted from this mode so original source controllers are not falsely applied at changed timeline coordinates. Source-pattern mode still retains them.

Parts are grouped by source track/program/percussion role. Only nonempty projected parts consume channels; at most 15 melodic parts use distinct channels while percussion shares channel 10 and one program. Initial MIDI programs remain patch approximations. Input limits: 256 total tracks, 2048 total clips, 128 note clips, 8192 notes/source and 65536 input notes. Output limits: 8192 notes/part, 65536 total notes, 4096 expanded source cycles/clip, one million absolute source cycle positions, source windows within ten million seconds and one million note/window evaluations. Standard writer tick/file/event caps and 480-PPQ quantization still apply. Budget violations fail before file publication.

### File-backed preview scope

New `audio_pcm_file.gd` bounds RIFF header inspection to 1 MiB/128 chunks and reads at most 16384 frames per request. It supports PCM8/16/24/32 and float32 mono/stereo, including standard extensible subformat GUIDs. `audio_file_preview.gd` supplies at most eight 2048-frame chunks per main process iteration to a native 0.75-second generator buffer.
