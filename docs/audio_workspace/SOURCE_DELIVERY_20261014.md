## Bounded file-backed source/preview increment

`audio_pcm_file.gd` reads RIFF PCM8/16/24/32 or float32 mono/stereo WAV metadata and small frame windows, including standard extensible PCM/float GUIDs. `audio_file_preview.gd` feeds a native AudioStreamGenerator from at most eight 2048-frame chunks per process iteration and a 0.75-second generator buffer. It never constructs a whole-WAV PCM resource. Main-thread disk reads/conversion can stall or underrun; this is not a low-latency streaming engine or a sample-accurate transport claim. RF64/compressed WAV, arbitrary channel layouts, sources above RIFF limits and asynchronous file I/O remain outside this reader.

Workspace WAV imports/relinks obtain duration from headers; FLAC STREAMINFO duration is also metadata-only. Long path sources use the existing background FFmpeg timeline renderer and then file-backed monitoring of its completed PCM. Preparation still renders the selected mix to disk before playback, so latency and disk space scale with the range. Native shared Scene actor playback remains unchanged. Path-based WAV waveform envelopes read bounded chunks in the existing background workers. Large whole-resource selection editing/analysis still requires a shorter source or rendered selection; MP3/Ogg resource loading, retained Undo/source resources and OS file caching are not a process-wide RAM guarantee.

Prepared preview file handles are closed before owned temporary paths are released/deleted. Native capture confirmed non-silent PCM and repeated seek in the WASAPI mixer; it is not a human listening approval. The FLAC byte-size preflight now uses the correct STREAMINFO offsets, covered by a regression fixture. See the requirement ledger for the complete validation batch and pending acceptance.
